Lesson 3: Accessing the Webcam with JavaScript

In Lesson 2, we converted an image into a tensor. Before we can process live images, we must learn how to access the webcam and display its video in a webpage.

This lesson uses ordinary JavaScript. TensorFlow.js will return in Lesson 4, when we convert webcam frames into tensors.

1. The video element

An HTML video element displays the camera stream:

<video id="video" autoplay playsinline muted></video>
AttributePurpose
autoplayStarts displaying the stream automatically.
playsinlineKeeps video inside the webpage on mobile devices.
mutedPrevents sound and helps autoplay rules; this lesson does not request audio.

2. Requesting camera access

The browser provides connected media devices through navigator.mediaDevices. We request the camera using getUserMedia(). 

const stream = await navigator.mediaDevices.getUserMedia({
  video: true,
  audio: false
});

video.srcObject = stream;

The browser asks the user for permission. If permission is granted, the returned MediaStream is assigned to the video element.

Important: Camera access normally requires HTTPS or localhost. The user must grant permission. A camera inside an iframe must also be explicitly allowed by that iframe.

3. Front and rear cameras

On devices with multiple cameras, facingMode expresses a preference:

// Front or user-facing camera
facingMode: "user"

// Rear or outward-facing camera
facingMode: "environment"

A desktop computer may have only one camera, so switching cameras may simply reopen the same device.

4. Requesting a suitable resolution

video: {
  width: { ideal: 640 },
  height: { ideal: 480 },
  facingMode: { ideal: "user" }
}

The word ideal means that the browser should try to use these values, but it may select another supported resolution.

5. Stopping the camera

A stream contains one or more tracks. We stop every track to release the camera: 

stream.getTracks().forEach(track => track.stop());
video.srcObject = null;
Always provide a visible Stop Camera button. Stopping the tracks is better than merely hiding the video because it releases the device.

7. Understanding common errors

ErrorLikely meaning
NotAllowedErrorPermission was denied or camera access is blocked.
NotFoundErrorNo suitable camera was found.
NotReadableErrorThe camera may be busy or unavailable.
OverconstrainedErrorThe requested camera settings cannot be satisfied.
TypeErrorThe page may not be running in a secure context.

Practice

  1. Start and stop the camera.
  2. Try switching between front and rear cameras on a phone.
  3. Change the ideal resolution to 1280 × 720.
  4. Display the actual videoWidth and videoHeight.
  5. Change the status message when permission is denied.

Privacy rules

  • Request the camera only after the user selects a button.
  • Clearly indicate when the camera is active.
  • Always provide a Stop Camera button.
  • Do not save or upload images without clear consent.
