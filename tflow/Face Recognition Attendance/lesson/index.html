Lesson 9

Face Recognition Attendance

An attendance system combines recognition with rules, timestamps, duplicate prevention and human correction.

By the end of this lesson, you should be able to explain the complete pipeline—not merely run the code.

Why this lesson matters

A camera sees the same student in many frames. Therefore, attendance must be event-based: a known person is marked only once, at the first acceptable recognition. The register—not the neural network—implements this business rule.

The pipeline

  1. Enrol authorized people
  2. Start a consent-based session
  3. Recognize at intervals
  4. Reject Unknown
  5. Mark a name once
  6. Record first-seen time
  7. Review and export CSV

Important terms

Attendance stateThe in-memory table of people already marked.
DebouncingPreventing repeated actions from repeated detections.
First seenThe timestamp of the first accepted match in the session.
CSVComma-Separated Values file that can be opened in a spreadsheet.
LivenessExtra checks intended to reduce photo or screen spoofing; not implemented here.

Key code

if (match.label !== 'unknown' && !attendance[match.label]) {
  attendance[match.label] = new Date().toLocaleString();
}

Read the chain from left to right: each stage adds information required by the next stage. A failure early in the chain affects every later result.

Checkpoints
  1. Why would marking every video frame create duplicates?
  2. Why is recognition alone insufficient for reliable attendance?
  3. Who should be allowed to correct a wrong record?

Run the action

  1. Open the action and select Load Models.
  2. Wait for the “Models ready” message.
  3. Provide the requested image or camera permission.
  4. Observe both the output and the status message.

Open action in a new tab

Troubleshooting

  • A student is not marked: check enrolment samples, light and threshold.
  • A wrong student is marked: stop, correct manually and review the threshold.
  • A photograph is accepted: this demonstration has no liveness protection.

Practice and assessment

  1. Require two consecutive matching scans before marking.
  2. Add class name, date and a Remove button.
  3. Export only after a teacher reviews the table.
Responsible use: obtain informed consent, minimize retention, secure biometric data, allow deletion and correction, provide a non-biometric alternative, and do not use experimental output as proof about identity, attendance, feelings, intent, health or honesty.
